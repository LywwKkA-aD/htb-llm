# HTB: методика решения машин в HTB LLM

## Окружение

- VPN поднимается внутри Kali-контейнера задачи (вкладка VPN): интерфейс `tun0`/`wg0`, адрес для обратных соединений — `$LHOST` в shell (`echo $LHOST`, проверить `ip -br addr`).
- Рабочая папка `/work` — там держать сканы, лут, скрипты. Инструменты на раздачу целям: `/opt/tools/linux` (linpeas.sh, pspy64, ligolo-agent), `/opt/tools/windows` (winPEASx64.exe, chisel.exe, ligolo-agent.exe).
- Вордлисты: `/usr/share/seclists/`, rockyou распакован в `/usr/share/wordlists/rockyou.txt`.
- Браузер хоста цели не видит: включить SOCKS во вкладке VPN и прописать в FoxyProxy/Burp, либо смотреть веб из контейнера (`curl`, `ffuf`).
- Важное по ходу сохранять в память задачи карточками: адреса, креды, работающие команды, найденный вектор. Новый чат подтянет подтверждённое сам.

## Порядок работы по машине

1. Поднять VPN, проверить связность: `ping -c2 <TARGET>`.
2. Имя машины в hosts контейнера: `echo "<TARGET> machine.htb" >> /etc/hosts` (и все найденные vhosts сюда же).
3. Быстрый скан всех портов, затем детальный по открытым (см. htb-01-recon-enum).
4. По каждому сервису — энумерация по профилю (веб, SMB, LDAP, БД...). Перед незнакомым сервисом искать в материалах: запрос вида `pentesting <порт или сервис>`.
5. Точка входа: веб-уязвимость, слабые/утёкшие креды, открытый сервис с RCE, известный CVE (`searchsploit`).
6. Стабильный шелл, апгрейд до TTY (см. htb-03-shells-transfer-pivot).
7. Флаг пользователя обычно `~/user.txt` (Linux) или `C:\Users\<user>\Desktop\user.txt` (Windows).
8. Локальная энумерация и повышение привилегий (см. htb-05-privesc), флаг рута: `/root/root.txt` или `C:\Users\Administrator\Desktop\root.txt`.
9. Каждую находку, которая пригодится после сброса чата или машины, — карточкой в память задачи.

## Правила хорошего тона на HTB и в этой песочнице

- Цели — только машины и сервисы, которые пользователь назвал сам (его инстансы HTB/лаб). Чужие адреса в VPN-сети не сканировать.
- Сканы ограничивать: `nmap -p-` один раз, дальше точечно. Брутфорс — с лимитами потоков и понятным вордлистом, не «весь rockyou по SSH» без причины.
- Длинный вывод не резать руками: полный результат сохранять в `/work` (`-oN scan.txt`) и делать выводы по полному выводу (`grep`, `wc -l`).
- Всё скачанное на цель (linpeas, chisel) держать в `/tmp` цели и называть нейтрально.
- Креды и хэши сразу фиксировать карточками памяти с указанием, где найдены и где работают.

## Частые грабли именно в Docker

- Reverse shell не приходит: проверь, что VPN поднят В КОНТЕЙНЕРЕ (`ip -br addr`, есть tun0), листенер слушает `0.0.0.0`, а в пейлоаде адрес `$LHOST`, не 172.23.x.x и не адрес хоста.
- Имя `machine.htb` не резолвится: добавить в `/etc/hosts` контейнера; DNS от VPN применяется только для OpenVPN с pushed DNS.
- Kerberos ругается на skew: время DC отличается. Использовать `faketime` вокруг impacket (см. htb-04-windows-ad).
- hashcat без GPU: CPU через pocl, быстрые хэши ок, bcrypt/Kerberoast только слабые пароли; тяжёлый крекинг — на хосте.
- Файлы, созданные на цели от root веб-сервера и т.п., могут не читаться: проверять вывод и коды возврата, не печатать «OK» через `||`.
